# Agent frontend

TanStack Start with React, TanStack Query, Vite, Tailwind CSS and locally owned shadcn/ui components. Dependencies are pinned to the npm `latest` tags resolved on November 7, 2026; Node type definitions follow the Node 24 runtime.

From the `agent` workspace root:

```sh
npm run dev --workspace @agent/agent-frontend
npm run build --workspace @agent/agent-frontend
npm run typecheck --workspace @agent/agent-frontend
npm run start --workspace @agent/agent-frontend
```

The development server uses `FRONTEND_PORT` (default 3000). Production uses Nitro's Node server at `.output/server/index.mjs`; `HOST` and `PORT` configure its bind address. Nitro's current latest release is a release candidate, as used by the current TanStack Start hosting guide. The route tree is generated by Vite; run the build once before a fresh-checkout typecheck.

The sidebar’s **WORKSPACE** section groups code directories under **Projects@<node name>** (for example, **Projects@frank-mbp.local**). When the node has no configured project directory, **chat_sessions** appears automatically and contains one directory per conversation. Expand a project or folder to browse its files and subdirectories; expanded listings refresh every three seconds and large folders offer **Load more**. Use the adjacent **+** button to add an existing directory on that node. The node validates and saves added roots; older browser-saved directories are imported on connection. Project names use the directory name. A project entry controls browsing; it does not change the node’s task workspace or tool permissions.

The left sidebar’s **MANAGE FLEET** section contains **My cloud**, **Connection settings**, and **Disconnect** when connected. Use **My cloud** to view and manage machine nodes.

Open **Connection settings** under **MANAGE FLEET** and supply the backend address (default `http://127.0.0.1:3100`) and its operator `API_TOKEN`. The token stays in tab memory, never local storage or URLs. The backend must allow the frontend's actual browser origin through its CORS configuration. Use HTTPS for remote backends; an HTTPS frontend cannot fetch an HTTP backend in browsers.

The app reads the real fleet and conversation APIs, sends revision-checked messages with an idempotency key, polls cumulative task output, displays routing reasons, and supports cancellation. An uncertain submission can be retried with the exact same request and key. The sidebar lists saved conversations by recent activity, using the first message as the title; select one to open its `/conversations/<id>` permalink and resume it. Opening a permalink directly loads that conversation after connecting to the backend. New conversation opens a local draft at `/` and makes no creation request until the first nonempty message is submitted; creation immediately navigates to its permalink without interrupting submission. Conversation navigation, including browser back/forward, is disabled while a task or uncertain submission is outstanding.

**Auto routing** uses Jev when enabled and permitted rules fallback; selecting a node pins the next task and never silently substitutes another node. The adjacent model picker defaults to **Auto model**. Choose a specific active, ready model to limit placements to nodes serving that exact model ID. With one matching node, routing goes directly to it without calling Jev. With multiple matching nodes, normal routing chooses among them. A model choice also constrains a pinned node; a mismatch blocks submission. The picker preserves an unavailable choice until you explicitly change it. Activate a downloaded inactive model from its node card before choosing it for chat. Tool permissions default to an empty list. Expand task permissions to select the workspace, enabled tools, hosted-judgment permission and rules fallback. The backend remains authoritative for eligibility and authorization.

Each inactive Ollama model has an **Activate** power icon beside its status. Click it to warm that model for subsequent tasks; the active model has no activation button. Activation buttons are disabled while the node is unavailable or busy, and show a spinner while preparing the requested model. Switching waits for active or unresolved tasks to finish, and the node becomes ready after warmup. The node saves the choice across discovery refreshes and restarts. Any downloaded local model can be activated manually, including Muse and models below 20 tokens/s. The speed minimum and other automatic-selection checks apply only to automatic selection; manual activation still requires successful warmup. Explicit runtime manifests continue to select their configured model.

Fleet and conversation-list polling run every three seconds, conversation polling every 1.5 seconds, and active task polling every 750 ms. This client currently uses authenticated polling rather than SSE; it replaces cumulative output snapshots and suppresses a temporary assistant output once the persisted message arrives. TanStack Query caches are isolated by connection and cleared on disconnect. No fake nodes or responses are supplied.

Each message has compact Copy, Delete, Like and Dislike icon buttons. The last message's actions stay visible; earlier actions appear on hover or keyboard focus and remain visible on touch devices. Copy writes the message text to the clipboard. Delete removes that message from saved history and future task context; it is disabled during active or unresolved tasks and pending submissions. Like and Dislike are placeholders.

Run `npm test --workspace @agent/agent-frontend` for output deduplication, pinned-node eligibility, unknown execution handling, connection URL validation and uncertain-submission retry behavior.

Add components using `npm run ui:add --workspace @agent/agent-frontend -- <component>`. `components.json` configures the Tailwind v4 stylesheet and source aliases.

Setup references: [TanStack Start](https://tanstack.com/start/latest/docs/framework/react/build-from-scratch), [Node deployment](https://tanstack.com/start/latest/docs/framework/react/guide/hosting), [shadcn installation](https://ui.shadcn.com/docs/installation/tanstack-router).

## Open a machine terminal

1. Open the frontend, then **MANAGE FLEET → Connection settings** and connect with the backend URL and operator `API_TOKEN`.
2. Open **My cloud**, find an online node, and click **Open terminal**.
3. Select its workspace or a registered project and **Persistent (tmux)**, then **New terminal**. If tmux is unavailable, explicitly select **Temporary (ends on disconnect)**.
4. Type directly in the terminal. Resize the browser to resize the PTY. Use **Detach terminal** or hide the panel to detach; persistent commands keep running.
5. After a refresh, reconnect to the backend and reopen the node panel. Select **Reconnect** for the existing session. **Take over** explicitly moves an attached tmux session from another tab. **End session** terminates it, or shows `ending` until an offline node is reachable.

Terminals use xterm.js with dynamically loaded terminal code. They do not require a model and remain available while inference is unavailable. Each panel labels host/container scope, OS user, persistence, idle/absolute expiry, and session limits. Losing a WebSocket never replays input or reconnects automatically. **Disconnect** revokes the current browser connection's tickets and detaches its writers; tmux sessions retain their configured expiry.
